# 测试说明

## 测试分层

| 层次       | 命令               | 文件                       | 验证什么                                                        |
| ---------- | ------------------ | -------------------------- | --------------------------------------------------------------- |
| 类型检查   | `npm run check`    | —                          | TypeScript 类型                                                 |
| 单元测试   | `npm test`         | `client/src/lib/*.test.ts` | 算法、输入校验、计算调度                                        |
| 端到端测试 | `npm run test:e2e` | `scripts/e2e.mjs`          | 打包后的单个 HTML 在真实浏览器里双击打开（file://）能否正常使用 |

## 单元测试

### `packing.test.ts`：算法基本性质

- 朝向去重：正方体只有 1 种朝向，两边相等时有 3 种。
- 单一方向：默认参数 28 个；整除边界（内径 12.1 装 1.1）没有浮点误差；放不下时返回 null；非法尺寸（0、负数、小数毫米、NaN）报错。
- 混合方向回归案例：
  - 100³ 装 5³ = 8000 个（旧版被截断为 1000）；
  - 61×44×70 装 11×8×20 ≥ 96 个（旧版贪心只有 75 个）；
  - 3×3 放 2×1 = 4 个（必须混合朝向）；
  - 41×39×44 装 21×17×21 = 8 个（必须用穷举搜索找到交错摆法）；
  - 38×31×29 装 7×19.5×22.5 = 8 个（低于理论上限 9，靠穷举证明最优）。
- 随机 300 组：方案合法（不重叠、不越界、朝向正确、数量一致），不少于单一方向，不超过理论上限。
- 极端输入（10m 大箱装 2.3×3.1×4.7cm）在时间预算内返回合法方案。

### `packing.reference.test.ts`：与独立精确解对照

测试内另写了一个暴力穷举求解器，不复用 `packing.ts` 的任何代码，用来求小规模案例的**真实最大值**。验证：

- 手工挑选的案例（包括需要交错摆法、低于理论上限的情况）结果一致；
- 随机小规模案例（最多 30 个，至少 20 个）结果全部等于真实最大值，「已证明最优」从不误报。

这是证明「结果正确」最直接的测试。修改算法后必须通过。

### `form.test.ts`：输入解析

- cm → 整数毫米（32.5 → 325）；
- 拒绝空值、非数字、负数、超过 1 位小数、超过 1000cm；壁厚允许为 0；
- 壁厚过大时，壁厚和对应尺寸同时提示；尺寸为空时不误报壁厚；
- 毫米转回 cm 显示时没有浮点尾巴（3 → "0.3"）。

### `runPacking.test.ts`：计算调度

- 没有 Web Worker 的环境（Node 测试环境）自动退回主线程，结果与直接调用一致；
- 非法输入返回失败，不会卡住。

## 端到端测试

```bash
npm run build
npm run test:e2e
```

自动查找本机的 Edge 和 Chrome（Windows / Mac 常见安装路径），有几个就测几个；也可以用 `BROWSER_PATH` 环境变量指定浏览器。用 `file://` 打开 `dist/装箱计算器.html`，依次验证：

1. 默认参数混合方向 33 个，理论上限 34；计算在 Web Worker 中完成（不卡界面）；3D 视图已渲染。
2. 切换单一方向：28 个，并提示混合方向可装 33 个。
3. 修改参数后出现「参数已修改」提示。
4. 交错摆放案例：8 个，已证明最优。
5. 100³ 装 5³：8000 个。
6. 放不下时显示「一个都放不下」。
7. 非法输入逐项提示，并且不计算。
8. 全程没有页面异常、控制台错误或任何网络请求。

截图保存在 `test-results/`（已加入 .gitignore），失败时会额外保存失败截图。

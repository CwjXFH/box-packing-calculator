# 算法说明

实现见 [client/src/lib/packing.ts](../client/src/lib/packing.ts)。

## 问题

把尺寸为 a × b × c 的同一种小箱子，尽可能多地放进 L × W × H 的大箱子内腔：

- 小箱子允许任意翻转（6 种朝向），边与大箱子的边平行；
- 箱子之间不能重叠，不能超出内腔。

这是「同尺寸长方体装箱」问题，属于 NP 难问题：不存在对所有输入都既快又能保证给出绝对最大值的算法。因此本程序对「正确」的定义是：

1. **输出的方案一定可行**：不重叠、不越界、数量与方案一致；
2. **尽量多**，且混合方向的结果**一定不少于**单一方向；
3. **诚实标注**：能证明是最大值时标「已证明最优」，否则同时给出理论上限。

## 数值表示

界面输入的 cm（最多 1 位小数）换算成**整数毫米**后再计算（[form.ts](../client/src/lib/form.ts)）。所有比较和除法都是整数运算，不会出现「12.1 ÷ 1.1 = 10.999…」导致少算一层的问题。

## 单一方向 `packSingle`

枚举小箱子的不同朝向（去重后最多 6 种），每种朝向的数量 = ⌊L/x⌋ · ⌊W/y⌋ · ⌊H/z⌋，取最大者。这是该约束下的**精确解**。

## 混合方向 `packMixed`

### 预处理：可拼长度

如果某个长度能写成 a·i + b·j + c·k（i, j, k 为非负整数），就称它为**可拼长度**。

**关键事实**：任何摆法都可以把所有箱子沿某个轴向原点方向推紧而不减少数量。推紧后，每个箱子在该轴上的坐标都是它前面若干箱子边长之和，也就是可拼长度。由此可以得出：

- 一段长度 d 中真正能用上的只有 `reduce[d]`（不超过 d 的最大可拼长度），子空间尺寸可以先缩减；
- 切割位置、箱子坐标都只需考虑可拼长度。

`buildReduceTable` 用一维动态规划求出每个长度是否可拼，以及对应的 `reduce` 值。

### 第 1 步：分块法（guillotine）

`solve(x, y, z)` 表示 x × y × z 空间最多能装几个，取以下两者中的较大值：

1. 整块用一种朝向排满：max over 朝向 ⌊x/o₀⌋·⌊y/o₁⌋·⌊z/o₂⌋；
2. 沿某一维在可拼长度 p 处切一刀，两块分别递归求解再相加。

优化：

- **旋转对称**：允许任意翻转，所以 (x, y, z) 的任意排列答案相同。记忆化时用排序后的三元组作键，状态数降到约 1/6。
- **只切一半**：切在 p 和切在 D − p 等价，只需枚举 p ≤ D/2。
- **剪枝**：若两块的体积上限之和都不超过当前最好结果，就跳过这一刀；达到本状态的体积上限后立即停止。
- **深度上限** 800 层，防止极端输入栈溢出。

第 1 种做法包含了单一方向的所有排法，所以结果一定 ≥ 单一方向。

### 第 2 步：穷举搜索（分支定界）

分块法只能表示「一刀切成两块」的结构。少数情况下，最优摆法是交错的（类似风车形），分块法做不到。例如内腔 41 × 39 × 44 装 21 × 17 × 21：分块法只能得到 6 个，真实最大值是 8 个。

当分块法的结果没有达到理论上限，并且网格规模不大（单元数 ≤ 6000）时，执行 `exactSearch`：

- 按三个轴的可拼长度把内腔划分成不等距网格；
- 按（高, 宽, 长）的顺序找第一个未决定的单元格：要么以它为角点放一个箱子（尝试每种朝向），要么认定它空着；
- 剪枝：已放数量 + ⌊剩余未决定体积 ÷ 单箱体积⌋ ≤ 当前最好结果 时放弃该分支；
- 以分块法的结果作为初始下界，剪枝更有效。

这个搜索是**完备的**：对任意推紧后的摆法，按上述顺序遇到的第一个空单元格，要么是某个箱子的角点，要么在该摆法中确实空着。因此搜索完整结束时，得到的就是真正的最大值。即使结果低于理论上限，也可以标记为「已证明最优」。

### 理论上限

upperBound = ⌊ reduce[L] · reduce[W] · reduce[H] ÷ (a·b·c) ⌋

依据是前面的推紧论证：所有箱子都能被推进 reduce[L] × reduce[W] × reduce[H] 的空间内。这个上限经常偏乐观，实际往往达不到。

### 结果标记

| 情况                   | `provenOptimal`       | `method`   |
| ---------------------- | --------------------- | ---------- |
| 分块法结果 = 理论上限  | true                  | guillotine |
| 穷举搜索完整结束       | true                  | exact      |
| 穷举找到更优解但没搜完 | 仅当达到上限时为 true | exact      |
| 规模太大不穷举，或超时 | false                 | guillotine |

## 时间与规模限制

| 项目                     | 值                            | 位置                 |
| ------------------------ | ----------------------------- | -------------------- |
| 尺寸范围                 | 1 ~ 10000 mm（0.1 ~ 1000 cm） | `MAX_DIMENSION_MM`   |
| 总计算时间（后台线程）   | 2 秒                          | `runPacking.ts`      |
| 总计算时间（主线程兜底） | 1.5 秒                        | `runPacking.ts`      |
| 穷举搜索网格上限         | 6000 个单元                   | `EXACT_MAX_CELLS`    |
| 分块法递归深度           | 800                           | `MAX_DEPTH`          |
| 3D 图最多绘制            | 30000 个箱子                  | `MAX_RENDERED_BOXES` |

超时后返回目前找到的最好方案，它仍然是可行方案，只是不一定最优。

## 实测表现

在 Node.js 下随机测试，大箱子 30 ~ 70cm，小箱子 3 ~ 25cm（0.5cm 步长）：

- 常见纸箱尺寸大多在几毫秒内完成；复杂情况最多用满 2 秒。
- 与独立实现的暴力精确解对照（小规模案例），结果全部一致，「已证明最优」从未误报（见 `packing.reference.test.ts`）。
- 相比旧版贪心算法：旧版在约 45% 的输入上比单一方向还少，并且有 1000 个的硬上限。新版不会比单一方向少，也没有数量上限。
